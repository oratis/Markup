# 出处入口

清账最贵的不是查，是**找入口**。姊妹书《星号之下》栽过一次：前三轮把"入口不对"误判成"东西不存在"，还把这个误判写进了"下一位不必重走"。这份文件是本书清账轮的入口表——**只登记实测取到过的地址，和实测 404 的写法**。

一手出处的分级与什么能打勾，见 [写作规范](写作规范.md) 与 [HANDOFF](../HANDOFF.md)。

**异体字会骗人**：`説郛`≠`說郛`、`楚辭集注`≠`集註`、`墓係銘`≠`墓系銘`、`酉陽雜爼`≠`雜俎`、

四库本《遗山集》作「貞祐甲**戍**」「犬**焉**之齒」（按正字通检会漏）。
**唐人选本裸书名一律 404，须带 `(四庫全書本)`**。

### 搜韵 API（这一轮最大的一个收获，全书通用）

第 13 章查出来的。**很多被判过「纸本不可及」的清人笺注，它直接给原文。**

```bash
# 取诗：系年、创作地点、诗序（Preface）、诸家笺注原文都在。
# **key 可以直接给诗句**，不必先过 QueryPoem.aspx 拿 id——后者连发即 429，
# 错误体只有 45 字节「自定义错误模块不能识别此错误。」，跟「查不到」一模一样；
# api. 子域不限流。
curl -sL -A "poets-book/1.0" "https://api.sou-yun.cn/api/Poem?jsonType=true&includeLinks=true&key=<诗句>"
# 作者小传与作者级评语
curl -sL -A "poets-book/1.0" "https://api.sou-yun.cn/api/Author?id=<id>"
```

冯浩《玉溪生诗集笺注》、沈德潜、姚培谦、《北梦琐言》的相关条目都是这样取到的；
李商隐《柳枝五首序》全文亦然。

**但要分清它给的是哪一种东西。** 搜韵有两样：**古人的笺注原文**，和**它自己的编年地图库**
（`AuthorDate` / `AuthorPlace`）。前者是一手的转载，可以据以打勾；**后者是今人编的，按
[写作规范](写作规范.md) §四·19 不够格当骨架依据**——第 16/14/17 组正是据此判了零翻案：
搜韵确实给出了系年，但那是它自己的库，不是年谱家的原话。它甚至会跟年谱家打架
（《凤凰台上忆吹箫》搜韵系 1109 青州，年谱家系 1121 莱州）。
**所以：搜韵是把清人笺注送到手边的通道，不是系年的权威。**

作者级的历代评语在 `api/Author?id=` 返回的 `Profile.Introductions` 里 `IsComment:true` 那几条
（篇级评语里没有的在这里）；`api/Comment` 路由存在但返回的是站内用户评论，不是古人评语。
**搜韵不收文**——王维、苏轼的文，key 一律返回 `null`。

**注意必须是 `api.` 子域加 `?id=`**——
`api.sou-yun.cn/api/Author?jsonType=true&key=…`、`/api/PoemAuthor`、`/api/AuthorProfile`、
`sou-yun.cn/api/…` 实测全 404。

## 三、两条从这一轮长出来的规矩

**1. 与正文冲突的二手摘要，必须再取第二个来源。**
核王洙杜集刻板地点时，第一份网络摘要说"杭州"，正文写的是"苏州"。照它改就会引进一个错——再查一次，确认是嘉祐四年王琪**知苏州**时所刻（万本，每部千钱）。**凡二手摘要与正文相左，先假定摘要错，再取一手。**

**00. 计数、列举、校字，一律用 curl 取原始 wikitext，不要用 WebFetch。**

```bash
curl -sL "https://zh.wikisource.org/wiki/樂府詩集/047卷?action=raw"
```

WebFetch 中间隔着一个会归纳的小模型，**你下多机械的指令都管不住它**。实测：《乐府诗集》卷四十七《春江花月夜》题下，原始 wikitext 的标题明写“春江花月夜二首（隋·煬帝）”、两首连排成一段，而 WebFetch 把它数成一首，害得正文被从“七首”错改成“六首”，并且连错误原因都诊断错了（以为是页面缺篇）。**凡是数目、篇目、名单、异文，走 curl。**

**01. 不知道一句话出自哪一篇时，用维基文库的 `insource:` 全站精确检索。**

三种写法都实测可用，任选：

```bash
# ① 网页检索（可加 prefix: 限定某部书）
curl -sL "https://zh.wikisource.org/w/index.php?search=insource%3A%22精确串%22&fulltext=1"
curl -sL "https://zh.wikisource.org/w/index.php?search=清明時節雨紛紛+prefix%3A全唐詩&fulltext=1"
# ② API 检索
curl -sL "https://zh.wikisource.org/w/api.php?action=query&list=search&srsearch=insource:%22精确串%22&format=json"
```

`prefix:书名` 用来**找**很好用；**用来判「没有」不行**。第 13 章实测：`prefix:` 只覆盖**转录索引页**——
《全唐诗》卷541、《全唐文》卷0771–0782、《樊川文集》卷01–17 都是几百到四千字的索引页，**只列篇名，没有正文**。
在这样的页上检索一句诗，必然零命中，而那个零毫无意义。第 12 章「《全唐诗》不收《清明》」后来是靠
**逐卷取杜牧八卷（520–527）的 raw 自己看**才落判的，不是靠 `prefix:`。


```
https://zh.wikisource.org/w/index.php?search=insource%3A%22要找的精确字串%22&fulltext=1
```

它按**原文精确串**在全站正文里搜，比猜篇名可靠得多。这是本轮定位一手出处最有效的一招（第 19 章查出）。**凡"知道有这句话、不知道在哪一篇"的条目，先走它。**

**01 之二、`api.php?list=search` 会限流。** 实测连发四次就报 `too many requests`，此后一段时间全返回错误——**而那个错误看起来跟「检索不到」一模一样**。两次检索之间要间隔，看到连续的空结果先怀疑限流，不要写进条目说"查不到"。

**01 之三、一次 404 不足以判「页面未建」。** 维基文库会偶发瞬时 404，返回一张约 1930 字节的错误页，重取即得。**判定不存在之前至少取两次**，并且看一眼返回体的大小。

**03（这一轮最重要的一条）. 检索不能用来证否。**

`insource:` 的负面结果**不可信**——实测 `insource:/文璧/` 的前三十条里**不含**那一页确实写着「文璧」的
《文山先生纪年录》。引号式还会因中文分词虚报：`insource:"陶夔"` 的 55 条命中里绝大多数是「臯陶、夔」
被切开的假命中，正则式 `insource:/陶夔/` 只有 2 页。正则式虚报少，但会因超时**漏报**。

**结论：检索只用来找线索。凡要落「某书没有这句／这个人／这首诗」的判断，一律把相关的卷
`?action=raw` 取回本地 grep。** 这一轮靠它翻出来的：刘禹锡《名子说》里的「咸允」（前两轮判无据）、
《重至衡阳伤柳仪曹》并引（四库本作「为别」，正字检索必漏）、《文选补遗》卷36 里陶渊明五子的大小名。
陶渊明章为一条「陶夔任太常」把《晋书》《宋书》《南史》十二卷约六十万字整个取回来 grep 过。

**04. `curl` 不加 `-A` 会被 Wikimedia 挡 429——而那张错误页跟「条目不存在」长得一模一样。**

第 11 章据此翻案：一条写着「成书年代确实查不到」的，其实是那次 429 把四家宋人目录整批漏掉了。
`/wiki/…?action=raw` 比 `index.php?title=…&action=raw` 更容易吃 429。

**04 之二（这一条推翻了好几条旧判断）. 四部丛刊本要用 `?action=render`，不是 `?action=raw`。**

丛刊本的分卷页 `?action=raw` **只回一个 `<pages…/>` 标签**（几百字节），看起来就像「有目无文的空壳页」。
换 `?action=render` 就是全文：

```bash
curl -sL -A "poets-book/1.0" "https://zh.wikisource.org/wiki/樂府雅詞_(四部叢刊本)/卷上?action=render"
```

**旧表里三条判断因此作废**：「《乐府雅词》是空壳页」、「《笺注陶渊明集》丛刊本序 259–550 字节空壳」、
「傅藻《东坡纪年录》须逐叶取 `Page:Sibu_Congkan…djvu/N`」。
`李太白全集/卷三十一` 那条「`raw` 只返 172 字节框架」也是同一个毛病。
**凡判过「空壳／有目无文」的丛刊本页，一律用 `render` 复验一次。**

**05. 批量验存页名用一次 API，别一个个撞。**

```bash
curl -sL -A "poets-book/1.0" "https://zh.wikisource.org/w/api.php?action=query&format=json&titles=A|B|C"
```

一次几十个，直接告诉你哪些页不存在（`missing`），**不会被那张 1930 字节的错误页骗**。

**02. 上一轮判「不存在」的书，多半只是入口写法不对。**
第 5 章实测：《唐摭言》《河岳英灵集》《唐才子传》上一轮全被记成「不存在」，**三本都在**。第 19 章实测：《文山先生纪年录》被记成「维基文库无」，其实就是《文山先生文集/卷17》；《指南后录》被记成 404，其实是 `/卷1上` `/卷1下`。
**凡看到前一轮写着「某书不在维基文库」，先用 `insource:` 或 `api.php?list=search` 复验一次再信。**

**0. 「查不到」之前，先确认你用的是不是全文检索。**
ctext 的 `searchbooks.pl` 只搜书名；用它搜正文，什么都搜不到，而这个「搜不到」毫无意义。全文检索的入口是 `post-han?searchu=`。**凡在条目里写「确实查不到」之前，回头看一眼自己走的是哪个入口。**

**2. 要机械的东西，就下机械的指令。**
核《乐府诗集》《春江花月夜》题下几首时，问"共几首、作者是谁"，两次得到不同的数（五首／七首）。改成"把每个作者署名与首句按次序一条一条抄下来，不要归纳、不要合并、不要计数"，一次就拿到了实情（六首，张子容两首）。**凡要计数、排序、列举，禁止对方归纳。**
