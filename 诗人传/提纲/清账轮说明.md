# 清账轮说明（2026-08-28 这一轮）

**派给清账 agent 的活，开工前把这份从头读一遍。** 姊妹书《星号之下》的清账轮把 1470 条清到只剩
13 条待核，靠的不是查得多，是这几条规矩守得住。

---

## 一、这一轮要达到什么

一句话：**你负责的那几个文件，章末 `<!-- 欠账: -->` 区块里的 `- [ ]` 要清空。**

三档的处置分别是：

| 档 | 记号 | 清完之后应该是什么样 |
|---|---|---|
| 待核 | `- [ ]`，无【成书前】 | **打勾 `- [x]`**，后面 `—— ` 接你查到的一手原文与出处；确实查不到的，仍留 `- [ ]`，但必须写明**是纸本不可及还是检索到底了**，并留下一位可以直接走的检索路线 |
| 成书前 | `- [ ]` 且带 `**【成书前】**` | 把证据链补全到**主编一眼能拍板**的程度，末尾写一行 `**建议：**…`。若证据本身已经把事情定死（不再是取舍，而是有答案），直接打勾并说明 |
| 已清 | `- [x]` | 不要动。除非你发现上一轮打错了勾——那就改回 `- [ ]` 并写 `**复核未通过：**…` |

**"清完"不等于"全部打勾"。** 留 C（不打勾）是合法结局，但**留 C 必须留路线**——上一轮有 93 条
清过却没写为什么没清，那是这一轮要顺手补掉的。

## 二、七条方法（都是前几轮栽出来的）

**1. 与正文冲突的二手摘要，必须再取第二个来源。**
清账最坏的结果不是没清，是把对的改成错的。凡二手摘要与正文相左，**先假定摘要错**，再取一手。

**2. 计数、列举、校字，一律 `curl "…?action=raw"` 取原始 wikitext，不要用 WebFetch。**
WebFetch 中间隔着一个会归纳的小模型，**你下多机械的指令都管不住它**。实测它把《乐府诗集》里
连排的两首并成了一首，害正文被从"七首"错改成"六首"，连错误诊断也是错的。

```bash
curl -sL "https://zh.wikisource.org/wiki/樂府詩集/047卷?action=raw"
```

**3. 本书自己已经引过的诗，就是现成的一手——写脚本在书内比对，不要上网重查。**
终章列的二十句月亮诗，十五句在各章引诗块里有全文，十几行脚本零次上网清掉十五条。
跨章重复的引文、生卒、系年，一律先在书内比对。

**4. 留 C 要区分"查不到"和"纸本不可及"。**
近人年谱（陈铁民、孔凡礼、朱金城、逯钦立、安旗、邓广铭、于北山、刘学锴余恕诚）多数不在网上。
写"纸本不可及"的意思是"去图书馆"，写"查不到"的意思是"换检索路线"——**对下一位意义完全不同**。
**但在写"纸本不可及"之前，先到维基文库搜一次书名**：四库全书本收了大量清人注本（仇兆鳌
《杜诗详注》、黄鹤《补注杜诗》都在），比想象的多。

**5. 边查边落盘。** 2026-08-25 有十二个清账 agent 同时被本机休眠打断，好几个已经查到了硬材料，
但一条都没写进文件，**全部丢掉重来**。**每清完两三条就立刻改文件，再查下一批。**

**6. 不要写 `/tmp`。** `/tmp` 在多会话之间共用，第 16 章的辅助脚本被另一个会话覆盖过。
辅助脚本写自己会话的 scratchpad。

**7. 重写欠账区块时，不要切到文件尾。** 上一轮有人用"从 `<!-- 欠账:` 截到 EOF"的写法重写第 1 章，
**把后面的 `<!-- 人物: -->` 与 `<!-- 年表: -->` 两个块一起删掉了**，而 `debt_report.py` 与
`style_audit.py` 都照报干净。**只替换到该区块自己的 `-->` 为止**，改完跑 `xref_check.py` 看有没有报缺块。

## 二之二、第二轮：专打「纸本不可及」

第一轮二十三个考据员各自做完，全书剩下 143 条判成「纸本不可及」的，压倒多数指向
近人年谱与清人笺注——陈铁民、朱金城、逯钦立、安旗、邓广铭、于北山、刘学锴余恕诚、
朱自清《李贺年谱》、王琦《汇解》、顾绍柏《谢灵运集校注》、孔凡礼《苏轼年谱》。

**这个判断在第一轮快收工时被一件事动摇了**：第 13 章查出搜韵有 API，而它给的正是这些东西——
系年、创作地点、诗序，**以及诸家笺注的原文**。它出现得太晚，前面二十几章一条都没用上。
所以有了第二轮：一人两三章，只碰那一档条目。

```bash
# 1) 用精确串拿 id：返回页里找 poem_title_<id>
curl -sL -A "poets-book/1.0" "https://sou-yun.cn/QueryPoem.aspx?key=<精确串>"
# 2) 取诗：系年、地点、诗序（Preface）、诸家笺注原文
curl -sL -A "poets-book/1.0" "https://api.sou-yun.cn/api/Poem?jsonType=true&includeLinks=true&key=<id>"
# 3) 作者小传
curl -sL -A "poets-book/1.0" "https://api.sou-yun.cn/api/Author?id=<id>"
```

**必须是 `api.` 子域加 `?id=`**；`?jsonType=true&key=…`、`/api/PoemAuthor`、`/api/AuthorProfile`、
`sou-yun.cn/api/…` 实测全 404。

第二轮的三种结局，**第三种和第一种一样重要**：

1. 搜韵或四库本注本给出了 → 打勾，**并把原来那句「纸本不可及」划掉、写明推翻的理由**。
   下一位要知道那句话作废了——第一轮就吃过前几轮误判的亏。
2. 查出正文实错 → 改正文，逐条报。
3. 两路都没有 → 仍留 `- [ ]`，但把「纸本不可及」升级成
   **「纸本不可及（搜韵 API 与四库本清人注本两路已试，皆无）」**。
   **这才是站得住的 C**：它告诉下一位这条已经走到哪一步、不必重走。

## 三、入口

**[出处入口.md](出处入口.md) 是入口表**——实测取到过的地址和实测 404 的写法都在里面，开工先读。
几条最常用的：

```bash
# 原始 wikitext（计数/列举/校字唯一可信的取法）
curl -sL "https://zh.wikisource.org/wiki/離騷?action=raw"

# 知道有这句话、不知道在哪一篇：全站精确串检索
curl -sL "https://zh.wikisource.org/w/api.php?action=query&list=search&srsearch=insource:%22精确串%22&format=json&srlimit=20"

# 限定在某部书里找
curl -sL "https://zh.wikisource.org/w/index.php?search=關鍵詞+prefix%3A全唐詩&fulltext=1"

# ctext 全文检索（searchbooks.pl 只搜书名，用它得出的"找不到"一律不作数）
curl -sL "https://ctext.org/post-han?searchu=關鍵詞"
```

补零规则各书不同：正史列传 `/卷190下` 三位数补零，**本纪不补零**（`/卷14` 通，`/卷014` 是 404）；
维基文库单篇**直取篇名**（`/wiki/離騷` 有，`/wiki/楚辭/離騷` 是 404）；同名多篇带 `_(作者)` 消歧，
且用的可能是**字**不是名（`/wiki/七哀詩_(曹子建)`）。

**你新试出来的入口（能用的、和实测 404 的）写进报告，主控统一回填 [出处入口.md](出处入口.md)。
不要自己改那个文件**——它是共享文件。

## 四、改正文的边界

清账查出正文有实错，**改**。但改之前记住这是**传记小说**，不是史话，边界见
[写作规范](写作规范.md) §四：

- **骨架层（生卒、籍贯、官职、科举、迁徙、亲属生死、诗的系年与本事）绝不虚构**，这一层查出错就改；
- **血肉层（天气、器物、饮食、衣着、路程）可以虚构但须合时代**，查出不合时代的（唐人坐椅子、
  唐人泡茶、唐代叫"状元"）就改；
- **声音层（对话、内心）有限虚构**：史料有记载的言行按记载写，不让人物说出后世评语，不编名言。

另外三条硬的：

- **传说不当骨架用**，放在"后来的人说""《集异记》里有一个故事"的位置上；**不用"订正"区块**。
- **不许出现章号互指**（"详见第 X 章"），穿线靠内容。
- **引诗块格式不许变体**：`> 《题》　纪年（公元）· 岁 · 地点`，`poems_check.py` 与
  `build_html.py` 都靠它。系年不详写"系年不详"，**不许编年份**。

改正文时另有一个工程陷阱：**全书引号形式混用**——正文多用半角 `"`，欠账区块用全角 `""`。
按字符串替换正文时会因引号形式不符而静默失配。**替换前先 `grep` 确认你要替的那一串真的在**。

## 五、只动自己的文件

**共享文件只有主控能改**：`README.md`、`HANDOFF.md`、`_manuscript.md`、`提纲/*.md`、`tools/*.py`。
人物谱与时间线的分章区是 `merge_blocks.py` 从各章末尾的 `<!-- 人物: -->` `<!-- 年表: -->` 块生成的，
**手改会被下次合并冲掉**——要改就改你那一章末尾的块。

跨章的事（同一个人在别章生卒不一致、同一首诗在别章系了另一个年、别章有你这章需要的结论），
**不要自己去改别章**，写进报告的"跨章事项"，主控统一处置。

## 六、交稿

改完跑这两个（**不要带 `2>/dev/null`，空输出不是通过**）：

```bash
python3 tools/debt_report.py            # 看自己那几篇的三档数
python3 tools/style_audit.py 你的文件    # 动过正文就要跑
python3 tools/xref_check.py             # 看有没有报"缺块"
```

报告写四段，不超过 400 字：

1. **数目**：清掉几条、留 C 几条（分别是纸本不可及 / 检索到底）、成书前剩几条。
2. **改了正文的地方**：逐条列，每条一行，写清楚原来错在哪。**没改正文就写"未动正文"。**
3. **跨章事项**：需要主控统一的（生卒打架、系年打架、别章结论）。
4. **新入口**：新试出来能用的地址，和实测 404 的写法。
