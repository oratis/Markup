## 二、这一轮生产的实况（供复盘）

22 章并行生产用了一夜，中途的失败模式值得记：

**1. 内容过滤会拦整章输出。** 屈原（自沉）、李贺（坟/血/呕心）、曹植（下毒轶事）、李白、陶渊明、李清照（家暴引文）、文天祥（狱中/就刑）、元好问（屠城/大疫）诸章的整章输出被 `Output blocked by content filtering policy` 拦下过，**agent 直接终止，文件一个字都没有**。两条对策，已写进派活模板：
   - **死亡与暴力一律一句话**，按正史本传的分量，不写身体、过程、行刑；张汝舟的家暴引文、曹彰被毒死的轶事这类，直接不写或改平。
   - **一节一次写入**（Write 第一节，之后逐节 `cat >>` 追加），并且**不要在动笔前把全章在思考里起草一遍**——预起草会让第一段就被拦。切小之后，被拦只损失一节，SendMessage 续上即可。
   屈原章五次失败后由主控亲写（主控上下文里同样的内容三篇都写成了）。

**2. 断连（ECONNRESET）与单次输出超限（64k token）**都出现过。前者 SendMessage 原地续写（agent 上下文还在，省一次重读资料）；后者也是"一节一写"解决。

**3. 会话用量上限**在凌晨三点前后触发（resets 4am），三个 agent 被打断。对策：`CronCreate` 定一个 4:07 的一次性唤醒，到点逐个 SendMessage 续写。**发现 agent 死于 limit 时不要立刻重发**，会再死一次。

**4. `completed` 不等于写完了。** 有 agent 在写完正文、没写报告时死掉（文件是完整的）；也有 agent 文件写了 7/8 节就死。**每次通知到达都先 `grep -c '^## '` 数节数、看文件尾巴**，再决定是续写还是验收。

**5. agent 的四行报告制度很值。** 每章报告里的"最不确定的三条骨架"直接进了该章欠账；"细纲异议"抓出了细纲的至少七处错（杜牧作《叙》时在宣州不在扬州、《求自试表》系 228、凤翔陷于 1231 春、白居易 805 年未被贬、"以卵击石"实为"驱群羊而搏猛虎"、《寄令狐郎中》系 845、雍丘王在 223）；"跨章事项"抓出了王维章的右拾遗错写成门下省（已改）、谢灵运章的甲子说错归萧统（已改）。

## 二之二、清账轮的四条方法（2026-08-24 这一轮长出来的）

**1. 与正文冲突的二手摘要，必须再取第二个来源。**
核王洙杜集刻板地点时，第一份网络摘要说「杭州」，正文写的是「苏州」。**照它改就会引进一个错**——再查一次，确认是嘉祐四年王琪知苏州时所刻（万本，每部千钱）。凡二手摘要与正文相左，先假定摘要错，再取一手。清账最坏的结果不是没清，是把对的改成错的。

**2. 计数、列举、校字，用 `curl "…?action=raw"` 取原始 wikitext——机械指令管不住 WebFetch。**
核《乐府诗集》《春江花月夜》题下几首时，问「共几首、作者是谁」，两次得到不同的数（五首／七首）。改成「把每个作者署名与首句按次序**一条一条抄下来，不要归纳、不要合并、不要计数**」，一次就拿到实情：六首，其中张子容两首。**凡要计数、排序、列举，禁止对方归纳。**

    **然后这一招自己翻了车，值得连着记住。** 据那次机械抄录，正文被从「七首」改成了「六首」；一天后取到程千帆《张若虚〈春江花月夜〉的被理解和被误解》，作「五家七篇」——**隋炀帝的《春江花月夜》本有两首，维基文库那一页缺了第二首**。机械指令忠实地数了一个残本。正文已改回七篇。
    **最后用 curl 取原始 wikitext 才定案**：页面一个字都不缺，标题明写「春江花月夜二首（隋·煬帝）」、两首连排成一段，**是 WebFetch 的摘要层把两首并成了一首**。也就是说，连「页面缺篇」这个错误诊断也是错的。

    **正确的做法是 `curl -sL "https://zh.wikisource.org/wiki/篇名?action=raw"` 自己数。** WebFetch 中间隔着一个会归纳的小模型，**你下多机械的指令都管不住它**；这一招由第 13 章的考据员查出，已写进 [提纲/出处入口.md](提纲/出处入口.md) 的第 00 条。凡是数目、篇目、名单、异文，一律走 curl。

**3. 本书自己已经引过的诗，就是现成的一手——用脚本对，不要上网重查。**
终章第四节列了二十句月亮诗。其中十五句在各章自己的引诗块里引过全文，写十几行脚本逐条比对，**零次上网当场清掉十五条**，并精确指出剩下五句（屈原《天问》、曹植《七哀》、陶渊明《归园田居》其三、白居易、刘禹锡《石头城》）才需要真去查。**跨章重复的引文、生卒、系年，一律先在书内比对。** `tools/xref_check.py` 做的是同一件事的另一面。

**4. 留 C 要区分「查不到」和「纸本不可及」。**
近人年谱（陈铁民、孔凡礼、朱金城、逯钦立、安旗、仇兆鳌、邓广铭、于北山）基本不在网上。凡欠账写着「须核某谱」的，多半只能留 C——但要写明**是纸本不可及，不是查不到**。这两件事对下一位的意义完全不同：前者要去图书馆，后者要换检索路线。姊妹书栽过的就是这一条：把「入口不对」误判成「东西不存在」，还把误判写进了「下一位不必重走」。

**5. 边查边落盘——查到的东西只有写进文件才算数。**
2026-08-25 有十二个清账 agent 在同一时刻被本机休眠打断，好几个已经查到了硬材料（《中山诗话》锦瑟条原文、《子刘子自传》、王宗稷《东坡先生年谱》的卷次），**但一条也没写进文件，全部丢掉重来**。派清账／写章的活，提示词里都要写死：**每清完两三条就立刻改文件，再查下一批。** 这跟起草时「一节一写」是同一条教训的两次出现。

**6. 长活开工前先挡住休眠。**
本机反复进入睡眠，是这一轮 agent 死亡的头号原因（错误信息是 `Your computer went to sleep mid-response` 与 `Agent stalled: no progress for 600s`）。开长活之前先跑：

```bash
nohup caffeinate -dimsu -t 21600 >/dev/null 2>&1 &
```

到点自动退出，不必手动收拾。**注意它挡不住合盖睡眠**，跨夜的活要么让机器插电开盖，要么把活拆小、勤落盘。

**7. 并行 agent 不要写 `/tmp`。**
第 16 章的考据员报告：它放在 `/tmp` 的辅助脚本**被另一个并行会话覆盖过一次**。`/tmp` 在多会话之间是共用的。派活时要求各 agent 只写自己会话的 scratchpad，或直接写进它负责的那个章文件。

**入口表见 [提纲/出处入口.md](提纲/出处入口.md)**——只登记实测取到过的地址，以及实测 404 的写法（例如维基文库单篇要**直取篇名**，`/wiki/楚辭/離騷` 是 404 而 `/wiki/離騷` 有）。

**主控自清的三篇**（序章、第 1 章屈原、终章）已清完，共清 40 条，其中改掉九处正文实错，最值得记的三处：
- 《楚世家》怀王二十四年是「楚往迎妇」——**楚国去娶秦国的女子，正文写成了「怀王把女儿嫁到秦国去」，方向反了**
- 《进雕赋表》原话是「自七岁所缀诗笔，向四十载矣，约千有余篇」，正文原作「四十岁以前的诗有一千多首」，与原文不合
- 序章原有一条「陆游后代死于崖山」查无实据，已撤，换成有据的林景熙《书陆放翁诗卷后》「来孙却见九州同，家祭如何告乃翁」——同样是死后六十九年，而且更锋利

**另外查出一条要主控统一的跨章事项**：《旧唐书》王维本传作「乾元二年七月卒」（759），与「年六十一」及其上元元年任尚书右丞的事实不合，通行作上元二年（761）。**这正是王维生年 701／699 之争的根子**，第 6 章的欠账要把这条写进去。

## 三、绝对不要做的事

1. **不要把史话的规矩搬过来，也不要把小说的规矩搬回史话。** 本书 §四 三层边界（骨架不虚构 / 血肉合时代 / 声音有限）是与两本姊妹书最大的分野。
2. **主角不经历传说；"后来的书上说"式引出每章 ≤2 次。**
3. **小说里不许出现章号互指。** `style_audit.py` 会查。
4. **引诗块格式不许变体**：`> 《题》　纪年（公元）· 岁 · 地点`。`poems_check.py` 和 `build_html.py` 都靠它。系年不详写"系年不详"，不许编年份。
5. **共享文件只能主控改**：`README.md`、`提纲/*.md`、`_manuscript.md`、`tools/*.py`。人物谱/时间线的分章区是 `merge_blocks.py` 生成的，**手改会被下一次合并冲掉**——要改就改该章末尾的块再重跑。
6. **不要用 `2>/dev/null` 跑检查脚本**；空输出不是通过。
7. 三份亲写稿（序、终、第 1 章）与两份主控补尾稿（第 7 章的编年表以下）在文风上以第 6 章为准绳；修订轮如果统一口径，**以正文多数派为准**，不要反过来改多数派。
