# 11 · 打开一个文件，就该看到那个文件

**状态**：已落地
**日期**：2026-09-07
**动机**：双击一个 `.md`，Markup 起来了，标签页也在，但屏幕上还是上次那篇。

---

## 1. 现象

> 「打开一个 md 文件后，总是还在上一个打开的 md 界面，不会自动切换到最新打开的。」

复现条件是「冷启动 + 会话里有大文件」：Finder 双击 → macOS 发
`RunEvent::Opened` → Rust 缓冲 → 前端启动时取出来打开。同一时刻，另一个
effect 正在把上次的标签页读回来。

## 2. 根因：两个 effect 在抢 `activeTabId`

改之前，`App.tsx` 里有两段互不相识的启动代码：

```
effect A（恢复会话）  readSession() → Promise.all(读 N 个文件) → …… → setActiveTab(sess.active)
effect B（OS 打开）   takePendingFiles() → 读 1 个文件 → openLoadedFile()  // 顺带 setActive
```

两条链谁后落地谁赢。B 是「取 + 读」两跳 IPC，A 是一跳并发读——文件小的时候
A 先完成、B 后完成，看起来一切正常；**只要会话里有一篇大文件**（这个仓库里
一本书动辄几百 KB），A 就慢到最后才落地，那句无条件的
`setActiveTab(sess.active)` 把焦点拽回上一次的文档。所以它对轻用户偶尔发生，
对天天开着一本书的人「总是」发生。

三个附带问题一并暴露：

- `setActiveTab` 不校验 id。会话里记的文件被删/改名后，`activeTabId` 指向一个
  不存在的标签页，`getActiveTab()` 返回 null，编辑器直接空白。
- `RunEvent::Opened` 既 emit 又缓冲。已经在跑的时候那份缓冲没人取，直到下一个
  窗口（⌘N）挂载时 `take_pending_files` 把它取出来——新窗口莫名其妙打开十分钟
  前双击过的文件。
- 标签条 `overflow-x-auto` 但从不滚动到激活项。标签多了以后新开的那页在可视区
  外，即使切换正确，眼睛看到的还是旧的那一排。

## 3. 方案：把「谁该在屏幕上」变成一条有序的流程

`src/hooks/useStartupTabs.ts` 接管这两段 effect，顺序固定：

1. **先注册** `open-files` 监听——启动期间来的 live open 不会漏。
2. **再打开 OS 交给我们的文件**，带焦点。用户在等这一篇，不是在等上次的标签页。
3. **最后在后台恢复会话**（`openLoadedFile(loaded, { activate: false })`），
   并且只有在**没人认领焦点**时才去 `setActiveTab(sess.active)`。

「没人认领」的判定在开标签页之前取快照：`activeTabId` 还是启动时那个 welcome
草稿 → 没人认领；已经是别的东西（第 2 步开的文件、侧边栏点开的、拖进来的）→
恢复流程闭嘴。

## 4. 辩论

**辩题一：恢复会话要不要干脆不设焦点？**

- 正方（不设）：最简单，永远不抢。
- 反方：那么正常启动（没有双击任何文件）时，用户回来看到的是会话里的**第一**
  个标签页，不是他上次正在写的那篇——这是明确的退步。
- **结论**：保留 `sess.active`，但加上「没人认领」这道闸。焦点归属由「谁是用户
  此刻的意图」决定，而不是由 IPC 谁先返回决定。

**辩题二：被双击的文件排在标签条的左边还是右边？**

- 正方（先恢复会话、再把它追加到最右）：标签顺序和上次完全一致，最保守。
- 反方：那用户得等整个会话（可能是几本书）读完才能看到自己双击的文件。启动的
  第一秒钟应该属于他刚点的那一篇。
- **结论**：要那一秒。双击的文件先开、在最左，恢复的标签页排在它右边。只有
  「冷启动 + 双击文件」这一种情况会改变标签顺序，普通启动的顺序不变。

**辩题三：Rust 端要不要引入「前端已就绪」的标志位？**

- 正方（不引入）：既 emit 又缓冲是「保险」，最多多一份数据。
- 反方：这份数据有生命周期——它会被下一个挂载的 webview 取走。多窗口下就是一个
  会自己打开旧文件的窗口。
- **结论**：引入 `FrontendReady`。前端注册完监听就调 `take_pending_files`，那次
  调用把标志位置起；之后只 emit，不再缓冲。窗口顺带 `unminimize + show +
  set_focus`——「切换到最新打开的」也包括把窗口本身端到用户面前。

## 5. 不在本轮

- **重新打开一个已开着的文件不刷新内容**。`openLoadedFile` 命中已有标签页时只切
  焦点，磁盘上的新内容不会进来（这是为了不吞掉未保存的修改）。要做的是「文件比
  内存新且标签页是干净的 → 静默重载」，那是 ReloadPrompt 那条线的事。
- **`.canvas` / `.html` 不能从 Finder 打开**。Rust 的 `is_markdown_path` 只放行
  `.md/.markdown/.mdx/.mkd`，而应用内是支持这两类的。要开需要同时改 Info.plist
  的 document types，单独一轮。
- **会话恢复失败没有任何提示**。读不出来的文件被静默丢弃；现在至少不会因此白屏。
